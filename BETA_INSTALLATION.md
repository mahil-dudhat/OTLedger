# OTLedger Beta Installation Guide

> [!WARNING]
> **BETA RELEASE & SECURITY WARNING**
> This is a BETA version of OTLedger. It is intended for testing and evaluation purposes only. **Do not host this application on a public server or expose it to the public internet.** Please review the [SECURITY.md](SECURITY.md) file before proceeding.

Welcome to the OTLedger Beta! This guide explains how to load the application using the provided Docker images, manage your accounts, and access the application from your devices.

## Prerequisites
Before you begin, ensure your server or local environment has the following installed:
*   **Docker Engine:** To run the containers.
*   **Docker Compose:** To manage the multi-container setup.

## Deployment Instructions

### 1. Preparation
Before you begin, ensure that you have downloaded and placed all of the following items in the **exact same folder** on your machine:
*   `db-init` (folder)
*   `docker-compose.yml`
*   `Github User Beta Trial_2026####.lic` (Your specific license file, the date/numbers will vary)
*   `otledger-app-1.0.0-beta.1.tar`
*   `postgres-16.tar`

Open your terminal or command prompt and navigate to this folder before proceeding.

### 2. Load the Offline Images
Run the following commands to load the images into your local Docker environment:

```bash
docker load -i postgres-16.tar
docker load -i otledger-app-1.0.0-beta.1.tar
```

### 3. Start the Application
Since you are already in the correct folder containing the `docker-compose.yml` file, simply start the database and web application:

```bash
docker compose up -d
```
*Note: The `-d` flag runs the application in the background (detached mode).*

### 4. Accessing the Application
Once the application is running, you can access the OTLedger web portal from your browser.

*   **From the same computer (Local Access):** Open your browser and go to `http://localhost:8080`
*   **From other devices on your network:** Open a browser on another device (like a phone or another laptop on the same Wi-Fi) and go to `http://<Host-IP-Address>:8080`. Replace `<Host-IP-Address>` with the actual IP address of the computer running Docker (e.g., `http://192.168.1.50:8080`). You can find this IP address by running `ipconfig` on Windows or `ip a` on Linux.



## Accounts & Passwords Management

OTLedger uses three distinct accounts to maximize security. **You must change these default passwords before deploying.**

### 1. PostgreSQL Admin (`postgres`)
*   **Purpose:** The superuser for the database server. It is used to initialize the database and run structural migrations. The web application does **not** use this account.
*   **Default Password:** `OTLedger@postgres2026`
*   **How to change:** Edit the `docker-compose.yml` file and change the `POSTGRES_PASSWORD` variable under the `otledger-db` service.

### 2. Application Database User (`otledger_app_user`)
*   **Purpose:** A restricted user that manages the application schema. It has permissions to automatically create and update application tables, but is isolated from administrative database functions.
*   **Default Password:** `OTLedger@appuser2026`
*   **How to change:** 
    1. Edit the `db-init/init.sql` file and change the password in the `CREATE USER` command.
    2. Edit the `docker-compose.yml` file and update the `Password` parameter in the `ConnectionStrings__DefaultConnection` variable to match.

### 3. Web Application Admin (Seed Account)
*   **Purpose:** The initial administrator account for the OTLedger web portal.
*   **Default Email:** `admin@otledger.com`
*   **Default Password:** `OTLedger@admin2026`
*   **First Login Instructions:** Navigate to the login page and use **`admin@otledger.com`** as your email address along with the default password to log in. Once logged in, upload the provided **`.lic` (License)** file when prompted, and then reload the application in your browser.
*   **How to change:** Edit the `docker-compose.yml` file and change the `Seed__AdminEmail` and `Seed__AdminPassword` variables before you run `docker compose up` for the first time.

## Data Storage & Volumes

Docker containers are temporary. To ensure your data survives container restarts or updates, OTLedger uses Docker Volumes. 

| Volume Name | Purpose |
| :--- | :--- |
| `otledger_db_data` | Stores the actual PostgreSQL database files. **Critical for data persistence.** |
| `otledger_uploads` | Stores files uploaded by users within the web application. |
| `otledger_backups` | Stores database backups generated by the application. |
| `otledger_logs` | Stores application diagnostic logs. |

*Note: If you need to wipe your installation entirely and start fresh, you must run `docker compose down -v` to delete these volumes.*

---

## Maintenance & Housekeeping

*   **Viewing Logs:** To see real-time logs from the web application, run: `docker logs -f otledger_app`
*   **Backups:** Regularly back up your database and user uploads.
*   **Stopping the App:** Run `docker compose down` (this stops the app but preserves your data volumes).
